# 面板升级后自动升级 Agent

管理员升级面板程序或 Docker 镜像后，面板默认让已启用升级能力的 Linux Agent 跟随当前面板的正式版本。无需逐台登录执行更新；离线节点恢复心跳后补升级。管理员可在「站点设置 → Agent 自动升级」关闭该功能，在「设备组 → 设备 → 节点运维」查看目标版本和升级状态。

## 首次启用

1. 使用包含此功能的完整面板发布包或镜像，保留原数据库与数据卷。对外地址必须配置为节点可访问的 HTTPS 地址；私有 CA 安装需沿用接入命令中的 `-c` 参数。
2. 新接入的设备会自动配置升级公钥。**已有设备需要重跑一次控制台接入命令**，保留原状态目录、证书、服务与检测 profile。脚本复用已有节点身份，配置 `-release-key /etc/tfp-agent/release-key.pub` 和监督进程，以后升级面板即可自动更新。
3. 节点运维显示「需重跑一次接入命令」时，说明 Agent 未启用升级能力或信任公钥不匹配。不要批量删除节点状态文件来解决。

仅替换面板可执行文件、遗漏 Agent 产物或发布清单时，设置页会显示不可用原因。旧 Agent 没有可信升级入口，无法由面板凭空完成首次初始化。自定义部署可自行配置公钥与 `-release-key`，但需要确保 Agent 对程序目录和状态目录具有写权限。

## 调度和验证

- 面板每 5 秒检查在线节点，整个面板安装同时最多升级 2 台。按 Linux amd64/arm64 分别选择产物，不支持的平台会显示原因。
- 自动升级只从已知的较旧版本升到面板的正式版本；不会自动降级，也不会自动跟随预发布版本。已完成的同一发布任务不会重复执行。
- 节点先验证 Ed25519 签名，通过 HTTPS 下载，并校验 SHA256；下载 URL 带校验值，面板换版后不会把不同二进制提供给旧任务。拒绝下载重定向。
- 升级任务复用持久运维队列与审计记录，自动任务不依赖管理员浏览器会话。管理员终端、卸载和手动升级仍使用原有权限校验。
- 下载失败等可重试错误最多尝试 3 次，前两次失败后分别等待至少 30、120 秒。管理员取消、升级成功或已回滚后，同一发布不会自动重试；确认问题修复后可手动升级或等待下一正式版本。
- 关闭开关会停止新任务与尚未领取任务。已经完成暂存并开始程序替换的升级由监督进程完成或回滚。

## 程序替换与恢复

下载先写同目录临时文件并同步磁盘，确认完整后原子替换，保留 `.tfp-previous` 旧程序。监督进程在转发工作进程外运行，工作进程退出时会关闭转发并结算信用窗口。

新工作进程须在 60 秒内完成真实的配置同步、配置 ACK、用量上报和探针上报，且运行版本与签名版本一致，才确认成功。无法启动、健康确认失败或替换过程中重启时恢复旧二进制，重新拉起工作进程，并持久记录回滚结果，待面板可达时回报。

普通 Agent 托管的入口和出口随工作进程一起更新。官方脚本安装的旧独立 `tfp-exit.service` 共用同一个程序文件：首次初始化时识别官方服务单元并写入 `managed-exit` 标记；仅对升级前正在运行且仍属于该安装的独立出口进行重启，回滚时也恢复其旧程序运行。自定义服务单元需要自行安排更新流程。

**升级会重启转发进程，现有连接会短暂中断。** 两台并发上限并不保证同一转发链路上的节点错峰；对断流敏感的场景，应关闭自动升级并安排维护窗口。回滚恢复的是程序文件，不回滚节点账本或配置；今后的 Agent 状态格式变更必须继续兼容上一版本，或在发布前暂停自动升级并另行迁移。

## 签名与发布产物

每个面板安装生成独立 Ed25519 签名私钥，保存在数据库表 `cp_agent_update_settings` 中；镜像更新和面板重启复用原密钥。正常数据库备份会包含此表。请备份并恢复原数据库，不能用新数据库代替升级。公开接口 `/download/agent-release-key` 仅提供公钥；安装脚本首次信任通过 HTTPS 获取的公钥，重复安装遇到公钥变化会停止，不会静默替换信任。

每个正式 Docker 镜像和 `scripts/release.py` 生成的手动发布包均包含以下同版本文件，运行时必须放在面板程序目录，或统一设置 `-agent-dir`：

```text
agent-linux-amd64
agent-linux-arm64
agent-release.json
```

清单通过 `go run ./cmd/agentrelease -dir <产物目录> -version <版本>` 生成。构建时必须把相同版本写入面板的 `main.Version` 与 Agent 的 `internal/agent.Version`；面板启动时核验清单版本、双架构 ELF、文件大小和校验值。产物校验失败会停用自动升级并展示原因，不影响面板其他功能。

管理员接口：`GET/PUT /api/v1/agent-update-settings`、`GET /api/v1/nodes/{id}/agent-update`。设置更新需带当前 `version`，防止多人操作覆盖；返回内容不包含私钥。

## 验证范围

代码测试覆盖签名与下载校验、原子替换与回滚、调度幂等、离线补升级、并发上限、失败退避、开关与权限，并提供 Linux 监督进程的成功升级、启动失败回滚和优雅停止测试。安装脚本测试模拟 Debian、Ubuntu、Red Hat 与 Arch 环境；模拟测试不等于真实发行版、生产网络与长连接迁移验收。

本次 Windows 工作区验证通过 Go 全量测试、相关竞态测试、`go vet`、前端类型检查与构建、三浏览器界面测试、安装脚本模拟测试及 ShellCheck；Linux amd64/arm64 面板与 Agent、发布清单已构建。Linux 专用监督进程测试已交叉编译，运行中二进制替换用例在 Windows 跳过；Linux 全仓竞态、三库、systemd 与双架构 Docker 验证以本版本 GitHub Actions 结果为准。尚未部署生产节点。
