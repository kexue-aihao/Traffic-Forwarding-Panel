# TCP 额度补充与混淆封装优化

2026-10-11，纳入 v0.1.44，基线为 v0.1.43（`68f3739`）。用户反馈单线程下载较上一版改善，但仍未达到预期。本次继续减少数据路径中的持久化等待和分配；公网速度需要在更新后的实际节点复测。

## 改动

- 将正常额度补充时的旧窗口进度和新窗口预留按顺序写入同一 WAL 批次，只做一次 `fsync`。原先一般需要分别同步进度和预留。新额度仍然只在同步成功后发布，旧的已落盘额度在同步期间可以继续使用。
- 计算批次中的预留时，扣除即将关闭的窗口数量，但仍保守保留尚未落盘的预算责任；多个请求共享同一批次时累计新预留。小租约需要方向再分配时仍先冻结并持久化结算。窗口、规则、账户、待上报记录和租约的容量上限保持原值。
- TCP 速率池能立即准许数据时，直接进行额度扣减；只有实际等待限速或补充额度时才创建超时上下文。仍执行每个数据块的速率、当前规则、租约有效期和额度检查。
- 混淆帧头和内容合并成一次底层写入，并在连接内复用读写缓冲。保留原线格式、随机填充和 TLS 校验；收发各有独立锁，支持分片读取和短写。
- TCP socket 继续继承所在网络命名空间的系统拥塞控制，不覆盖机器已经配置的 BBR。

WAL/checkpoint 格式仍为 2。额度不足时 TCP 暂停等待，UDP 保留原来的丢包语义。每窗口最多 256 KiB、每方向两个窗口、每规则 1 MiB、每账户每 Agent 8 MiB 的未确认责任上限保持不变。正常退出结算实际准许的用量；异常退出仍保守结算无法证明未用的预留余量。

## 吞吐验证

Windows amd64、Intel i5-10400F、Go 1.26.9。真实 TCP 回环、单条持续下载连接，TLS 验证测试 CA，使用 `random-padding`，运行实际 Runtime/Store；每轮 4096 × 32 KiB（128 MiB），预热 16 块，重复三轮。有限租约足够大，没有面板控制循环或租约续期。基线和改动版本使用同一基准源文件；基线通过临时 Go overlay 还原上述提交的计量和混淆源码。

可复现当前版本：

```sh
go test ./internal/agent -run '^$' -bench '^BenchmarkSecureDirectDownload$' -benchtime=4096x -count=3 -timeout=3m
```

基准同时报告业务吞吐、每 32 KiB 的 WAL 同步次数、同步平均耗时和分配。`secure_direct_metered_3ms` 在每次真实同步前额外等待 3 ms，用来对照较慢磁盘的影响；它不是用户服务器磁盘延迟的实测。

| 模式 | v0.1.43 三轮 MB/s | 优化后三轮 MB/s | 三轮均值变化 |
| --- | --- | --- | --- |
| 安全直连，不经过计量 | 383.56 / 381.09 / 359.46 | 520.12 / 475.93 / 460.51 | +30% |
| 安全直连，实际计量 | 179.99 / 185.05 / 191.68 | 323.05 / 323.47 / 334.46 | +76% |
| 实际计量，每次同步额外等待 3 ms | 31.77 / 31.73 / 31.84 | 62.05 / 63.69 / 63.13 | +98% |

正常计量每 32 KiB 的同步次数从 0.2520–0.2534 降至 0.1260–0.1262。对应分配从约 86 KiB/28 次降至约 44 KiB/15 次；这些统计包含完整隧道和后台计量。额外 3 ms 模式中，真实同步加注入等待的总耗时约 3.9–4.0 ms。比较采用同一进程环境的相邻两次运行，存在调度波动；裸 TCP 对照也出现过单轮离群值。应以多轮和同步次数的变化评估，不按一次峰值推断公网带宽。

## 正确性验证

新增回归验证进度和预留只需要一次同步、同步期间不能使用新额度、同步期间旧窗口继续扣量不会丢失用量、追加/同步故障恢复幂等，以及 WAL 在两条进度记录之后或新预留记录内部截断时不恢复预算。现有并发双向扣量、责任上限、小租约、空闲回收、撤销配置、续租和正常关闭测试继续适用。混淆回归覆盖原帧格式、短写、连续帧变大再变小，以及 17 字节读取。

本地通过 Go 全量测试、`go vet ./...`，Agent/tunnel/probe/integration 的 race 检查，以及新增 TCP/混淆用例多轮运行。Linux amd64/arm64 交叉编译通过，未在本地 Windows 上运行 Linux 内核测试。前端通过类型检查、生产构建和 Chromium/Firefox/WebKit 契约测试；时间提示验证三秒边界、跨时区、零/未知/非法值、旧 Agent、SSE 重启、离线、键盘/触屏和窄屏边界。

三浏览器的真实 Go/SQLite 面板测试和共享 TLS 配置界面测试也通过。补上旧面板探针兼容后，重新通过 Agent 全套 race 检查及 Agent/integration 回归。

## 探针时间提示

鼠标悬停、键盘聚焦或触屏点击开机时长时显示启动时间和当前时间，统一为上海时间 UTC+8，当前时间每三秒从浏览器时钟更新。Agent 新增可选 `booted_at`，读取操作系统启动时间；旧 Agent 没有该字段时用 `sampled_at - uptime_seconds` 估算并标注。估算不使用变化中的浏览器时间，离线时启动时间不会随刷新漂移。无数据或非法时长显示未知；重启后的 SSE 上报会更新已经打开的提示。

新版 Agent 上报含 `booted_at` 的探针若被旧面板以 HTTP 400 拒绝，会立即重试同一采样的原格式。仅成功重试才缓存兼容模式，五分钟后再次尝试新字段，便于面板升级后自动恢复。鉴权、网络或服务器错误不触发这种降级。已用严格旧面板响应及失败响应测试覆盖该行为。

本地复测包位于 `.local/tcp-refill-test-20261011/`，版本 `0.1.44-tcp-refill-test`，包含 Linux amd64/arm64 归档、校验和及操作说明。已核对 ELF 架构、CGO、版本链接参数和工作区构建信息；原生 Windows 构建验证了 `-version` 输出，Linux 二进制尚需在实际节点运行。新悬停界面需要包含本次前端产物的面板。

本机吞吐不能换算成公网 VLESS 性能保证。复测应记录入口/出口实际 Agent 版本、单线程目标速度、相同路径直连基准和混淆策略，使用相同客户端/目标、持续至少 30 秒、重复三轮。
