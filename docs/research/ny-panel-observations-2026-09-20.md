**转发和设备组应补充的需求**

- 入口直出有禁止、可选、强制三种策略；用户可用的入口和出口受用户组及入口/出口互相限制影响。
- 设备组与物理机器并非一一对应：一个组可包含多台服务器，需要分别管理组策略、机器会话、在线状态与权重。
- 链式出口前端存在每跳出口与 Mux 设置、重复出口检查，当前脚本限制 2–3 跳。该限制只是参考版本行为，新产品的最大跳数应单独确定。
- 转发支持多个目标地址和 IPv4、IPv6、域名表示；高级表单包含负载均衡、接受/发送 Proxy Protocol、规则限速、IP 数和连接数限制。
- 前端列出的负载策略包括随机、轮询、IP Hash、最小连接数和故障转移。实际调度算法、权重与健康检查需在节点验证。
- 批量导入分为新增和按端口匹配修改；应补充导入预览、逐条错误、冲突提示和部分失败结果。
- 存在 TLS 入站、母/子规则端口共享、SNI、回源 TLS 行为和反向连接相关前端配置。尚未验证握手、证书校验和节点执行。
- 规则状态包含未同步、正常、同步失败、禁用；新产品需要配置版本、节点确认和错误原因，避免把“数据库保存成功”等同于“已生效”。

上述功能中，协议屏蔽尤其需要独立设计。实际设备组配置出现 `blocked_protocol`、`blocked_host`、`blocked_path`、`disable_udp`、`tls_inbound_policy` 等字段；本轮读取到的屏蔽协议值为 `http`、`socks`、`fet`。`fet` 的语义与识别边界没有证据，不能擅自解释为某个具体协议。

新增设备组的基础表单没有直接显示协议屏蔽的多选控件。新产品应按用户要求，在新增和编辑设备组时提供该控件，并区分传输层禁用、隧道类型限制、应用协议识别、域名及路径规则。应记录识别失败、误判、策略优先级、节点版本支持和生效状态；加密内容不能仅凭配置字段就保证可识别。

**TLS、WS、WSS、HTTP 的证据边界**

出口协议下拉框实际显示 `ws`、`http`、`tls_simple`；页面脚本还识别 `tls` 展示值。当前部署的设备组显式 `protocol` 值只观察到 `ws`，缺省值的含义待验证。未在该下拉框看到独立 `wss` 选项，不能据此认定后端不支持，也不能认定已经支持。

`wss://.../api/v1/system/node/status_ws` 是探针推送连接，它不能证明转发数据走 WSS。浏览器到面板的 HTTPS 也不能证明入口与出口之间加密。WS/HTTP 自身不提供传输加密；新产品需分别定义承载协议、TLS 开关、证书/SNI、鉴权、多路复用、UDP 封装和回源安全性。

**支付、套餐与资金功能**

支付通道表单实际列出 `epay`、`epusdt`、`tokenpay`、`cyber`、`cryptomus`。字段包含名称、启用状态、URL、商户号、密钥、回调 Host、手续费比例。这里只验证配置入口和查询响应，未创建充值订单、访问外部支付网关或验证回调。

管理员支付配置接口与用户支付信息接口返回不同字段集。用户查询响应只观察到最小充值额、通道名称/类型/启用状态/费率；管理员查询可返回商户配置字段。新产品应明确用户接口的字段白名单，并避免在普通列表中返回可用密钥。

参考产品的主流程是“充值到钱包 → 使用余额购买套餐”。套餐类型包括月付、日付、不限时流量包和可叠加流量包；另有隐藏套餐、套餐属性推送、自动续费、兑换码、人工记账、补单、邀请返佣和佣金转余额。

前端说明中，立即续费可能重新计算到期时间并重置流量；购买可能覆盖当前套餐。新产品必须明确叠加、替换、提前续费、剩余流量和套餐删除后的处理规则，不能默认照搬这些行为。

需要新增的商业完整性要求包括：支付通知验签、金额/币种/订单匹配、重复与乱序通知处理、主动查单、账本、对账、退款与拒付状态、支付费率展示，以及账务与套餐发放的一致性。是否接入支付宝/微信直连、Stripe、PayPal 等，应列出具体渠道验收清单；参考站点未证明这些渠道存在。

**探针、真实公网 IP 与运维**

HTTP `/api/v1/system/node/status` 和 WebSocket `/api/v1/system/node/status_ws` 均有实际响应。新旧探针在本轮均收到状态推送，数据按设备组组织，组内为服务器列表。

| 数据类别 | 实际出现的字段或页面信息 | 仍需验证 |
|---|---|---|
| 身份与在线 | 组 ID/类型、服务器 handle/name、online、last_seen、last_pull、weight | handle 稳定性、重连合并、重启与过期语义 |
| IP | ip4、ip6、v4/v6 地区；页面称“出口 IP” | IP 是 Agent 上报、外部探测还是面板连接来源；多出口如何选择 |
| 实时网络 | net_in_speed、net_out_speed、net_in_transfer、net_out_transfer | 单位、网卡范围、采样周期、重启/回绕、与计费的关系 |
| 资源 | CPU、内存、磁盘、部分 Swap、负载、进程数、TCP/UDP 连接数 | 采样来源、缺失值处理、容器与宿主机范围 |
| 系统 | CPU 型号、系统/版本、架构、虚拟化、启动时间、主机名、Agent 版本 | 采集权限、节点升级兼容性 |

设备组的 `connect_host` 在前端被明确标注为“仅前端显示”，因此不能作为机器真实公网 IP 的证据。新产品应分别呈现可连接地址、实际出口 IP、网卡地址和面板观察到的连接来源，并带上来源与更新时间。

探针前端还包含权重调整、节点升级、清理离线节点和远程终端入口。仅观察到入口/调用逻辑，未执行。远程终端属于可选运维能力，若纳入产品，应设置独立权限与审计，不能随普通探针查看权限开放。

当前新探针页面额外加载 `/tool/capture.js`，其中有 `/ext/api/me/context` 与 `/api/capture/report` 等站点扩展逻辑。查看该页面时拦截了两次自动报告 POST，未向该扩展提交本次捕获的会话或响应。脚本里的候选探测路径没有被当作有效接口清单，也未逐一枚举。这部分是否需要迁移应由站点部署配置进一步确认。

**其他待补充与待验证事项**

- 邀请配置和设备离线通知配置的 KV GET 本轮返回 404；前端仍存在相应设置页。原因可能涉及缺省配置、版本或部署，当前证据不足以定位。
- 本轮没有证实独立 API Token、细粒度权限、历史监控留存、审计日志、证书自动续期、备份恢复或多数据库兼容。
- SQLite/PostgreSQL/MySQL 是新产品的明确要求，无法从网页抓包判断参考站点的实际数据库实现。
- 服务端调试还需面板机、测试入口/出口、指定测试流量与普通用户身份，详见下一轮验证计划。没有 SSH 条件时，本轮网页/API 层成果已可用于需求评审。
