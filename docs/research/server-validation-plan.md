**下一轮服务器与测试环境验证计划**

浏览器抓包已经确认页面、查询接口和探针数据结构。服务器调试用于核实节点到面板、入口到出口的实际行为。只有面板服务器通常不足以验证隧道加密、应用协议识别和转发计费，最好另有一个测试入口和一个测试出口；两者也可以是隔离的测试容器或虚拟机。

**需要提供的连接与范围信息**

| 信息 | 用途 |
|---|---|
| SSH 主机、端口、用户名、本机已有密钥路径或本机 SSH 别名 | 连接指定机器；无需在文档或聊天中粘贴私钥 |
| 机器角色：面板、入口、出口；部署方式与版本 | 定位进程、容器、配置、日志及网络路径 |
| 允许操作的测试节点/设备组，以及测试端口范围 | 明确可建立测试规则和产生少量测试流量的位置 |
| 普通测试用户及资源权限 | 验证两端权限、用户间隔离、隐藏节点与探针字段 |
| 是否有测试支付通道、商户沙箱及测试订单 | 验证真实回调与账务流程；无测试通道则保留待验证 |
| 可用权限：日志读取、容器查看、限定接口抓包、测试服务启停 | 根据验证项目使用实际需要的权限；不默认要求全程 root |

本轮没有 SSH 连接条件，因此没有声称已经完成下列服务器验证。获取连接信息后，先核对实际部署和测试资源，再执行依赖这些条件的步骤。

**验证项目与预期产物**

| 项目 | 操作范围 | 要核实的问题 | 产物 |
|---|---|---|---|
| 部署拓扑 | 读取服务/容器和反向代理配置，配置中的密钥不输出 | 面板、Agent、定制探针脚本、数据库和入口出口分别在哪里 | 拓扑、组件版本、接口归属 |
| 节点心跳 | 一个指定测试节点 | 鉴权、心跳周期、断线宽限、会话保留、重连身份、last_pull 含义 | 状态变化时间线 |
| 配置下发 | 测试组与测试规则 | 拉取/推送机制、版本、确认、错误、重复下发、离线恢复 | 配置状态机与字段补充 |
| 真实公网 IP | 指定测试节点及已认可的 IP 查询目标 | 网卡 IP、NAT 出口、IPv4/IPv6、多出口、面板看到的连接源是否一致 | IP 来源对照表 |
| 资源与带宽 | 指定测试网卡与短时受控流量 | 单位、采样、容器/宿主范围、网卡聚合、计数器重启和缺失值 | 指标定义与误差记录 |
| TLS/WS/WSS/HTTP | 测试入口、出口与自有目标服务 | 实际承载、握手、证书校验、加密范围、TCP/UDP、Mux、重连与超时 | 协议能力矩阵及限定范围抓包摘要 |
| 协议屏蔽 | 隔离测试规则 | http/socks/fet 含义、域名/路径匹配、加密识别限制、误判与策略优先级 | 允许/阻断样例、日志与边界说明 |
| 计量与限额 | 测试用户、有限字节量与有限连接 | 原始与计费流量、倍率、方向、限速、IP/连接数、到期和超额 | 账单与节点计数对照 |
| 故障转移 | 指定测试节点 | 权重、下线剔除、恢复、现有连接、失败回滚 | 故障时间线 |
| 用户权限 | 两个普通测试身份与管理员 | 横向/纵向资源访问、隐藏节点、敏感字段、API Token 权限 | 权限矩阵与结果 |
| 支付闭环 | 沙箱/测试商户和测试订单 | 验签、重复/乱序通知、查单、超时、补单、退款及重复发放 | 支付状态机与账本核对 |
| 多数据库 | 新产品实现后各自隔离数据库 | SQLite/PG/MySQL 的相同业务行为、事务、迁移和恢复 | 兼容性验收结果 |

**采集方式**

- 先确定目标 IP、端口、网卡与时间窗口，再使用 tcpdump/tshark 等工具采集对应测试流量；设置时间、文件大小和轮转上限。
- HTTPS/WSS 网卡包通常只有握手和密文。字段调试继续依赖浏览器可见响应、授权的服务端日志或测试服务，不能把密文 PCAP 当作已读取业务内容。
- 每个实验记录配置、版本、动作时间和预期结果；抓包关联测试规则，避免混入其他用户的真实业务内容。
- 导出字段结构、统计与必要的脱敏片段。原始 PCAP 若含敏感数据留在指定调试位置，不直接提交到产品仓库。
- 测试资源的创建、策略变更、断线模拟和支付流程仅在明确的测试范围内进行；本轮线上观察不包含这些操作。

完成后更新需求文档中的证据状态，并逐项记录“通过、失败或条件不足”，不会将表单出现某个选项等同于功能已经验证。

**与需求 v0.2 的衔接**

参照 [产品需求](../product-requirements.md) 中的 D01–D15 决定实际测试口径，参照 [验收场景](../acceptance-scenarios.md) 记录可重现步骤。服务器抓包只解决技术事实，不能代替用户决定支付渠道、计费公式、续费方式和首版范围。

本计划中的 ny 调研与新产品验收应分别记账：参考产品行为只能提供证据和设计参考，新产品仍须在自身实现上重新验收。三库一致性、数据恢复与性能测试尤其不能由参考站点结果替代。

v0.2 新增的重点验证包括同机多组端口分配、配置旧回执与重复下发、面板失联期间权益/撤销行为、流量重复/乱序/迟到、双栈/DNS/出站绑定，以及指标未知值与公网 IP 来源。涉及修改或故障模拟的项目仍使用明确的测试资源；当前仅制定计划，尚未执行这些实验。
