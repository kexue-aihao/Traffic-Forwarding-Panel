**需求完整性复核 · v0.3 · 2026-09-20**

复核对象：[产品需求文档](product-requirements.md)、[ny 观察报告](research/ny-panel-observations-2026-09-20.md)、[接口清单](research/ny-api-inventory-2026-09-20.md)和用户原始描述。历史抓包证据保持原样，现已进入实现阶段，见 [实施状态](implementation-status.md)。

结论：v0.3 包含 9 项明确要求、48 项细化条目、36 个验收场景。D01–D15 已记录确认口径；容量、延迟、保留期和平台目标已写入，具体吞吐、误差和恢复基线仍需实验完善。Cyber 按2026-09-21用户指示跳过；测试商户与参考容量环境属于外部依赖；需求完整不等于实现及验收完成。下表保留 v0.2 复核历史，当前决定以主文档 v0.3 为准。

**发现并修正的缺口**

| 问题 | v0.2 处理 | 意义 |
|---|---|---|
| 原文描述 ny 的 `/admin` 被写成新产品已经确认的路由 | 改为建议路由，放入 D15 | 避免把参考产品事实误写成用户决定 |
| 充值、账本入账和套餐发放合成一条流程 | 拆分钱包充值、余额购买和可选套餐直付 | 防止重复发放权益或同时增加余额 |
| 证书验证整体处于 P1 | R28 改为 P0 加密基线 / P1 自动化 | 不因分期交付一个不验证证书的 TLS/WSS 基线 |
| 所有支付通道被默认要求支持关闭订单 | 改为能力声明及不支持时的晚到支付处理 | 防止虚报第三方网关能力 |
| 只有菜单名称，没有两端页面与权限分工 | 增加页面和角色矩阵 | 能逐页评审并逐接口验证隔离 |
| 四种隧道只是名称，没有承载和失败定义 | 增加协议矩阵、TCP/UDP、DNS、超时和缓冲边界 | 将“支持协议”变成可执行验收 |
| 同机多组的端口冲突未覆盖 | 增加 R36 与监听资源约束 | 防止跨组并发分配同一物理资源 |
| 屏蔽协议、隧道协议和加密内容识别混在一起 | 分层定义，保留未知协议与加密不可见边界 | 界面选项和节点能力相符 |
| 限额、到期与面板失联之间缺少约束 | 增加 R40、离线权益和撤销延迟决定 | 避免“无限离线可用”与“即时撤权”互相矛盾 |
| 金额、流量、时区、倍率变更没有具体边界 | 增加状态表与 R41 | 可对账、可重试、可解释历史 |
| 数据库支持仅停留在连接选择 | 增加三库一致性、并发迁移和空环境恢复 | 覆盖真正可部署及恢复的产品能力 |
| 批量操作缺少任务和并发编辑语义 | 增加 R39 | 部分失败、重试、取消和页面刷新后有稳定结果 |
| 账号恢复、初始化、维护、删除引用没有展开 | 增加 R33/R34/R42/R48 | 覆盖日常运营和无法登录/无法升级等场景 |
| 界面异常状态、帮助、审计与性能未形成范围 | 增加 R43–R47 与 N01–N08 | 发布前有可检查的质量要求，候选功能不自动承诺 |
| 没有逐需求的验收映射 | 新增 A01–A32 和下表 | 防止后续实现完成后找不到测试依据 |

**完整程度与后续边界**

| 层次 | 当前结论 |
|---|---|
| 原始要求是否丢失 | 未发现遗漏；九类均有需求和验收映射 |
| 模块清单是否可评审 | 可以；覆盖管理端、用户端、Agent、探针、商业、API、数据库和运营维护 |
| 异常和跨模块关系是否展开 | 已补齐当前识别出的主要场景，包括并发、重试、离线、撤权、计费及恢复 |
| 业务规则是否最终确定 | 主要规则已确认并写入 D01–D15；Cyber 已跳过，外部测试环境仍缺失 |
| 性能是否可以直接验收 | N01/N03/N04/N06/N08 已有基线；其余发布目标需要实验锁定 |
| 技术能力是否已证明 | 部分 ny 页面/API 已观察；实际隧道、支付、普通用户权限、IP 来源和 Agent 行为仍待验证 |
| 是否已决定全部实现 | 已授权分阶段完整交付，含已选择高级能力；其他未选择候选项不自动纳入 |

需求决定主要来自用户的运营目标；它们不必等待服务器才能讨论。技术证据则按 [服务器验证计划](research/server-validation-plan.md) 补充，尤其不能把采集到字段等同于真实功能生效。现按已确认 D 项实施，发布前按 A 场景提供证据。
