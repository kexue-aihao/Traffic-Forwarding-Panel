# 设备组共享 TLS 入口

## 工作原理与适用范围

设备组管理员配置一个 TLS/TCP 监听地址。每个入口节点独立预留该端口，不依赖用户父规则或任何规则租约。获设备组授权的不同账户可创建自己的 SNI 路由，客户端连接相同入口地址并发送规则的业务域名。

Agent 有界读取 ClientHello，按可见 SNI 选择规则，再运行该规则的策略、检测计划、资源池及有限租约，通过直连或既有出口隧道转发。已读取字节只回放一次。共享入口默认不终止 TLS、不提供入口证书；客户端验证目标服务的证书，该证书必须覆盖业务 SNI。SNI 只负责路由，不代替业务认证。

配置受控业务 TLS 的规则仍进入原有 TLS 终止/协议检测处理链；共享入口不会让透传 TLS 内层协议变得可见。普通 TCP、原生 UDP、空 SNI、未知 SNI 不接入此入口。ECH 内层域名不可用于路由；仅能按客户端实际暴露的外层名称匹配。首期只支持精确 DNS 名称，不支持通配路由或默认目标。

## 管理及 API

在设备组高级设置添加「设备组共享 TLS 入口」，激活完整高级策略并启用。例如：

```json
{
  "policy_version": 2,
  "shared_tls_ingress": {
    "enabled": true,
    "listen_ip": "0.0.0.0",
    "port": 443
  }
}
```

该配置用于组内每个入口节点。默认关闭；监听 IP 默认 `0.0.0.0`，端口默认 `443`。只允许管理员配置入口组。共享端口不受独立规则 `port_min/port_max` 范围限制，继续执行组的网络、直出、出口、身份授权和账户规则数量限制。

规则界面选择该组入口后，新 TCP 规则默认勾选按 SNI 路由；填写客户端实际使用的域名。需要独立端口时取消勾选，仍须满足设备组 TLS 策略。普通 TCP 及 UDP 使用独立监听。已有规则不自动迁移；旧父子共享规则继续使用原有同账户权限和生命周期。

创建规则的 API 示例（其他必需规则字段按原 API 提交）：

```json
{
  "listen": "",
  "shared_tls": {
    "ingress_id": "group",
    "server_name": "app.example.com"
  }
}
```

`group` 在创建时解析为稳定的组/节点入口 ID。平台生成监听地址，拒绝不一致地址及其他组/节点的入口 ID。域名规范化为小写 ASCII，移除尾随点，国际化域名转换为 IDNA；IP、通配名和重复 SNI 被拒绝。`ingress_id` 和旧 `parent_id` 互斥。已有规则的入口归属不可改变；编辑时可留空 `listen`，平台使用当前组地址。

Agent 必须声明 `shared-tls-ingress-v1`。配置通过 `Config.tls_ingresses` 下发；没有能力的节点不收到入口和关联规则，界面显示升级需要及规则阻断原因。`tls_inbound_policy=1` 要求 TLS；`2` 允许授权用户使用共享入口，独立端口仅管理员可创建。

同一入口最多预留 64 个 SNI（包括禁用草稿），运行时最多 256 个并发连接；握手继续受现有超时、字节与进程检测并发限制保护。接收 PROXY protocol 需要独立监听，共享入口允许原有支持范围内的出站 PROXY 行为。

## 运行生命周期与隔离

SNI 路由表在配置应用时整体替换，每条路由独立拥有取消上下文和连接归属。增加规则不关闭已有连接；删除、禁用、权限撤销、目标/策略变更及限额降级只关闭受影响规则。正常续租沿用连接，但后续数据使用最新规则租约计费。停止一个租约不会关闭其他规则。

删除最后一条规则后，管理员入口继续监听，未知 SNI 仍拒绝。关闭入口、改变监听地址或配置有效期过期会关闭入口相关连接。更换端口先预留新端口，旧端口在节点确认成功应用新配置后释放；失败 ACK 不释放。监听 IP 在同一端口由通配地址改为具体地址时，必须先关闭旧 socket 和流，再绑定新 socket；配置失败会尝试恢复原 socket。

端口冲突继续采用仓库的保守物理节点规则：相同节点、网络及端口跨所有 IP 互斥，普通规则、出口及不同组共享入口均参与检查。新增表 `cp_tls_ingresses`、`cp_ingress_ports` 为增量迁移，适用于 SQLite、PostgreSQL、MySQL，不改变旧 `cp_ports` 外键。

管理员可在高级设置查看节点能力、应用失败、等待确认、离线，以及入口路由数、连接数和拒绝次数。Agent 使用 `Ack.tls_ingress_statuses` 上报监听状态与拒绝分类，不上报业务内容、SNI 明细或本地密钥；普通用户节点列表不暴露跨账户入口统计。

共享规则导入使用 `create` 模式，重新执行权限、入口和 SNI 检查；`update_by_port` 拒绝共享规则，因为一个端口无法唯一标识规则。导出保留入口 ID、SNI 和当前监听地址，重新部署到其他组/节点时需改用目标入口 ID 或 `group`。

## 验证及上线

Go socket 测试覆盖真实 TLS 证书验证、独立目标、直连/出口、账户计费、路由热更新、续租、租约停止、限额变更、空/未知 SNI、明文 TCP、分片握手、64 条并发路由、配置过期、同端口 IP 重绑/回滚及容量拒绝。真实控制面/Agent 集成测试验证用户授权、完整 TLS 入站策略与 Host 禁用实际生效、监听状态上报和关闭入口后 ACK 释放端口。平台测试覆盖跨账户授权、并发重复 SNI、独立端口冲突、旧 Agent、导入、端口更换/关闭及成功/失败 ACK 行为，可用 `TFP_TEST_DRIVER` 在三种数据库运行。

浏览器检查：`node scripts/test_tls_ingress_ui.mjs`，使用真实面板和 SQLite，在 Chromium、Firefox、WebKit 验证高级配置、默认共享、隐藏父规则/监听字段、规则编辑和独立端口覆盖。该测试使用禁用草稿；启用后的转发由 Go socket 测试验证。

基准：`go test ./internal/agent -run '^$' -bench BenchmarkTLSIngressRelay -benchtime=1s`。本机 Windows/amd64、32 KiB TLS 回环和实际计量路径的一次测量为旧 64 路由 11.58 MB/s、新单路由 14.56 MB/s、新 64 路由 14.00 MB/s，均约 104 次分配/轮。单轮请求平均耗时约 2.25–2.83 ms；这些值受本机磁盘、调度和 TLS 开销影响，不是公网吞吐、P99 或长稳性能承诺。

上线先升级面板及 Agent，再于测试设备组启用并确认实际监听。配置默认关闭，不迁移旧规则。回退功能时先关闭共享入口并等待节点 ACK；规则不会自动改为独立端口，已使用新入口的节点不得直接降级旧 Agent。
