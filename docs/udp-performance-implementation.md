# UDP 改进实现与验收记录

日期：2026-10-09。基线：v0.1.37 / `3e0364b9834b5b0173fd8236fb80d5608dfee129`。

用户已经批准 [计划书](udp-performance-plan.md) 的实施，并随后授权提交、推送和发布 v0.1.38。本次代码覆盖直连 UDP 和普通单出口 QUIC DATAGRAM，并提供独立压测工具。**功能验证通过不等于性能验收通过**：Linux 跨机容量、延迟和 24 小时稳定性仍待隔离环境验证；三库回归由发布 CI 执行。版本发布不代表已经部署到用户的入口或出口服务器。

## 参数与计量语义

- 每窗口最多 256 KiB，每方向最多两个；单规则未完成责任最多 1 MiB，同账号单 Agent 最多 8 MiB。小额预算按剩余额度缩小；方向间必要时由后台冻结、结算、再分配，不等待逐包磁盘操作。
- 普通计量记发送前已授权的业务字节。队列拒绝、策略拒绝、限速拒绝不计量；发送尝试失败可能已计量。UDP socket / QUIC 提交成功均不证明对端收到。
- 异常退出按未关闭窗口的未确认责任上限恢复，`kind=recovery`；正常记录为 `normal`。每个事实绑定原租约、权益周期、窗口和递增序号，重试使用相同 ID。单次崩溃可能多计上述有限预留，重复崩溃的恢复责任累计增加。
- 商业租约预算是加权后的有限套餐占用：单租约最多 256 MiB、账户跨节点未退还占用最多 512 MiB，每规则最多四个未退还租约。旧能力节点仍使用 16 MiB 单租约。空闲或极小流量不提前占满套餐。
- 待报用量加窗口恢复槽合计最多 4096。Agent 保留租约元数据最多 16384；已确认退还、已过期且不被当前配置/用量/窗口引用的历史通过原子快照清理。未过期标记保留，阻止同一预算再消费。状态容量耗尽时停止新授权。
- 当前面板固定下发每规则 1024 个会话；Agent 配置契约支持上限 4096，尚无管理员调整会话上限的界面。Agent 合计最多 4096 个 UDP 会话、128 个 UDP 监听器、32 个同时建连任务。监听 worker 队列 64 包，会话发送队列 64 包，等待建连最多 8 包，队列报文存储合计最多 64 MiB。
- Linux 会话接收缓冲固定 4×65535 B，监听器固定 16×65535 B；还需要计入 OS socket 缓冲、QUIC 库和协程内存，64 MiB 队列上限不是进程总内存上限。4096 个直连会话仅用户态目标接收缓冲上界就接近 1 GiB，部署验收需按机器资源限制并发会话与规则规模。
- 入口每端点复用一条 QUIC 连接，端点池最多 64；出口最多 64 条连接、全局 1024 个业务会话、32 个并行目标创建。每连接发送队列 256 项/8 MiB、接收队列 8 MiB、重组 8 MiB，每会话最多四个未完成重组、1 秒到期。

默认 DATAGRAM 数据帧上限 1240 B，其中协议头 25 B；1200 B 业务报文通常一帧。库报告较小上限时自动减小并分片，业务丢片不会重传，也不阻塞后续报文。分片的恢复不是可靠交付机制。

规则诊断增加 UDP 接收、提交、队列/额度/限速/策略/容量/I/O 丢弃计数；Linux 增加 `SO_RXQ_OVFL` 和实际收发缓冲值。该内核计数需要收到后续报文才能观察，不能代替网卡和全局 UDP 统计。QUIC 诊断另给连接数、业务流数、队列/重组占用和应用丢弃；提交帧数不代表网卡发送数，库内部/网络丢包应通过接收端校验和 Linux 统计交叉验证。计数随进程或监听器重建重置。

## 配置单出口

1. 升级入口及出口注册 Agent，使其上报 `udp-credit-v1`、`udp-datagram-v1`、`lease-set-v1`。面板按能力下发可选字段，旧节点不接收新字段。
2. 普通出口进程在已有 TCP 承载之外配置 `-udp-listen 0.0.0.0:9443`，沿用证书/私钥与 `TFP_EXIT_TOKEN`。安装器新增 `-D '0.0.0.0:9443'`；接入页面可生成命令。UDP 绑定失败在启动时直接返回错误。
3. 管理员“出口管理”启用原生 UDP，填写 UDP 端点、证书校验名称、凭据。这个凭据必须等于出口进程实际配置的 token；当前 CLI 的 TCP/UDP listener 共用该环境变量。token 只写不读，编辑原端点时留空可保留。
4. 开通入口到出口 UDP 端口；TCP/UDP 可使用相同数字端口，面板分别预留。同机器的监听端口不以域名/IP区分；已有出口也由 schema 12 迁移预留。旧共享端口保留每个所有者，新冲突拒绝。
5. 创建 UDP 规则并选单出口。两端支持时使用 QUIC；管理员 `udp_over_tcp` 强制旧承载。无能力节点仅在管理员显式允许兼容回退时用 TCP；网络封锁 UDP 不会静默切换 TCP。
6. 使用受控回显目标验证实际收发与规则诊断；QUIC 建立成功仅证明认证/会话创建，不能当作目标 UDP 已送达。

## 本地验证证据

已执行 `go test ./...`、`go vet ./...`、Windows build、Agent/tunnel/integration/udpbench/storage 的 race 检查，Linux amd64/arm64 build 和 Agent 测试二进制交叉编译，OpenAPI 142 条操作生成/校验，以及 UI typecheck/build 和 Chromium/Firefox/WebKit 浏览器回归。

功能测试包括 0/1/64/1200/8192/60000 B 报文、QUIC 1200 B 单帧、证书名/token 拒绝、缺失分片后续报文、32 个共享连接会话、撤销/租约切换、慢建连容量、有限套餐跨租约、窗口责任限额、小额方向再分配、磁盘短写和 WAL 崩溃恢复。有限 64 MiB 套餐的 direct/quic 集成测试每个场景累计 7500×1200 B 上下行回显，即 18,000,000 B，超过首个 16 MiB 分配；该测试证明持续转发与计量关系，不证明高 PPS。

此前本地 smoke：Windows amd64、Go 1.26.9、12 逻辑 CPU、1200 B、1000 PPS、1 s 预热/2 s 采样。B0 单会话 2002 包全部返回；B1 32 会话 2000 包全部返回，均无校验丢包。原始报告在 `.local/udp-b0-smoke.json` 和 `.local/udp-b1-smoke.json`。这两轮会话数不同且与其他测试同时运行，仅证明工具可用，不能据此比较性能或宣称达到计划门槛。

以下仍待性能验收：Linux 批量 I/O/IPv6 的容量、跨机 B0/B1/B2/V37 同条件吞吐、Linux amd64/arm64 性能、受控 MTU/RTT/丢包/乱序/NAT 重绑定、完整故障注入矩阵与 24 小时长稳。本地功能测试使用 SQLite；仓库发布 CI 另运行 Linux race、真实 MySQL/PostgreSQL 事务回归与 systemd 安装/卸载，结果以本版本对应 CI 记录为准。

## 升级和回滚

Agent 状态升级为 WAL 2 / `TFPWAL02`。旧裸 JSON、WAL 1 和 checkpoint 1 可读取并先迁移，既有用量保留；旧程序明确拒绝新格式。数据库新增 schema 12 的物理出口端口预留，计量分类继续存入原不可变用量 payload。

升级前在 Agent 停止时备份整个状态组合（快照、`.wal` 和相邻恢复文件）及面板数据库，先在隔离副本验证。不可只恢复快照而遗漏 WAL，不可运行两进程共享状态，也不可通过删除状态恢复预算。

数据面回滚可先取消出口 UDP 配置并明确选旧承载，继续使用新 Agent 结算/退租。需要降级 Agent 二进制时，先正常停止所有规则，刷新用量并取得全部用量和退租确认，保存完整新状态与审计，再采用另行审查的状态迁移或受控重新注册流程。当前没有 WAL 2 → WAL 1 降级转换器，**不能直接把旧二进制指向新状态**。旧备份在新版本已消费额度后也不能直接恢复，否则可能重复花费预算。

性能验收门槛沿用原计划：1200 B 直连 ≥ B1 的 90%；单出口 ≥ B2 的 85% 且 ≥同拓扑裸 UDP B1 的 80%，并满足 PPS/延迟/丢包/24 h/计量要求。用户在本地实现完成后另行授权版本发布；v0.1.38 提供已实现功能，不宣称已经达到上述性能门槛。在完整 Linux 证据产生前，状态保持“代码功能验证通过、性能验收待测”。

跨机测试命令与报告模板见 [验收操作手册](udp-performance-lab.md)。
