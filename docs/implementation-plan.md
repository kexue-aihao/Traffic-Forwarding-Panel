# 动工计划与责任边界

2026-09-20 用户授权实施。需求基线 [v0.3](product-requirements.md)，接口基线 [v1](api-contract.md)，验收 [A01–A36](acceptance-scenarios.md)。这是执行计划；阶段完成必须有代码与实测证据。

架构：Go 模块化控制面 + 独立 Go Agent + Vue 双入口。database/sql 显式版本迁移；SQLite 本地 WAL、有界优先级写队列，PG/MySQL 同一业务语义。首版三库单控制面实例。Cookie 会话和带权限的 API Token 分离，节点身份独立。期望配置、节点回执、支付状态、钱包账本及权益版本各自存储，可靠事务与 outbox 驱动可重试副作用。

| 子智能体 | 独占职责 | 协作与门禁 |
|---|---|---|
| A：前端与设计系统 | web/**、生成嵌入资产、浏览器回归；用户/管理员界面 | 不自行定义账务或后端字段；唯一资产生成者；遵守 M09 |
| B：控制面与数据库 | 身份授权、组/机器/端口/规则、配置协调、探针过滤、三库、任务审计 | 不能绕过 D 直接修改账本；审核商业迁移的三库兼容 |
| C：Agent、隧道与探针 | Agent、四承载、策略执行、真实计量、持久补传、高级拓扑 | 不直接改钱包；真实 TCP/UDP 流量、证书失败与资源回收验证 |
| D：支付、计费与权益 | 五渠道、订单/尝试、钱包账本、套餐续费、配额租约、退款返佣 | 使用公共身份和事务边界；金额整数、精确倍率、幂等与对账 |

主智能体负责公共契约、根依赖/CI、迁移编号、集成与发布验收。四个不同角色轮换执行；平台线程/并发上限为四（含主智能体），同时最多三个子任务。使用独立 worktree/branch，提交后集成，公共字段修改先同步，避免跨工作区覆盖文件。

P1 先建立真实数据库、配置、去重与财务热路径并做早期实验，再扩大业务页面。前端基础组件可以并行；早期实验未通过时不可宣称已获完整容量结论。

容量基线：500 节点、10,000 用户、100,000 规则；探针每5秒、500订阅；20,000活跃后100,000全活跃、10秒计量批次；每秒150读+20写+5财务。三库总参考资源各16vCPU/32GiB/本地NVMe，独立压测机。P95≤300ms、P99≤1s、意外错误<0.1%，在线配置/探针≤10秒；早期2小时、发布24小时。空库和满留存数据均测，500节点重连；1小时常态积压30分钟追平，无重复钱/权益/计量、跨用户数据或未报告丢失。原始精确计费不由探针近似替代。

实施中已确认不可变规则：CNY分、UTC存储/上海显示；续费从购买成功时间重新算自然月并夹紧月末，不沿用旧到期、不月初加送额度；入口上下行×入口倍率×出口倍率，直出出口倍率1；未知协议默认允许并标记；24小时离线上限受套餐到期/已分配额度限制，未归还额度不能再分配；普通用户API/推送/导出隐藏真实IP。
