# v0.1.5

修复重复运行 Docker 安装脚本只启动旧容器、没有升级镜像的问题。从本版开始，同一条命令支持首次安装和已有安装升级：

```sh
curl -fsSL https://github.com/kexue-aihao/Traffic-Forwarding-Panel/releases/download/v0.1.5/install-docker.sh -o install-docker.sh && sudo bash install-docker.sh
```

已有旧版会先下载、校验并导入目标镜像，再停机备份整个安装目录，更新 `.env` 的 `TFP_IMAGE` 并重建容器。账号、数据、端口、域名、支付设置、Compose 和覆盖文件保持不变。升级成功须同时通过健康检查、容器镜像 ID 和程序版本校验，不能仅凭 `Healthy` 判定升级完成。

同版本重复执行只启动并验证，不重新下载或备份；脚本拒绝自动降级和同目录并发操作。`--bundle` 离线升级使用同一流程。首次安装选项不覆盖已有设置，也不重设管理员密码。

备份位于安装目录旁的 `traffic-forwarding-panel.backup-日期-随机后缀/installation.tar`，包含停机后的数据库与原配置。下载或校验失败不停止现有容器；备份失败会尝试启动旧容器。新程序启动后若验证失败，会保留备份并报错，不会自动将旧程序连接到可能已迁移的数据库。回退需同时恢复升级前的数据和配置。

自动备份适用于安装器默认的 SQLite 数据目录。外部数据库、自定义镜像和目录外数据挂载需手动备份并升级，详见 [部署说明](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.5/docs/docker-deployment.md)。安装脚本需要 Docker Compose v2 和 util-linux 提供的 `flock`。

回归覆盖首次安装、镜像替换、原密码与登录会话保留、自定义配置保留、冷备份、重复执行、损坏包拒绝、降级拒绝，以及备份失败和新容器健康检查失败的处理；两个架构均执行实容器验证。本版延续 v0.1.4 的流量连续性和探针 1024 进位修复；入口/出口 Agent 需另行升级。
