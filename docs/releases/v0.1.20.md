# v0.1.20

新增转发规则的弹窗里，「入口服务器」和「设备组」原本是两个下拉：一台机器一个名字、一个组另一个名字，而规则实际落在的是两者的组合，组里只有一台机器时更是同一件事说了两遍。现在合成一个「入口服务器」，选项文字就是**设备组名** —— 选中一次同时定下机器和组。只有当一个入口组里不止一台机器时，选项才补上机器名（`组名 · 机器名`）加以区分；编辑一条入口已经不在组里的旧规则时，列表里补一条只读项，显示这条规则实际落在哪里，而不是给一个空下拉。

这一步暴露出一处后端问题：`GET /nodes` 对普通用户会把每台机器的 `group_ids` 整个置空。置空确实挡住了越权（一台机器可能还属于别人的组），但「机器 + 它所属的入口组」这条组合也就永远凑不出来，普通用户建规则时看到的是空下拉。现在改为与探针列表一直以来的做法一致：**只返回这个身份有权访问的那些组**，别人的组仍然不会出现。这是 `/nodes` 响应的一处行为变化 —— 普通用户会看到 `group_ids`（限于自己有权访问的组），此前为空。

浏览器 fixture 覆盖「组里多台机器」的分支，真实 Go/SQLite 后端的集成测试覆盖「组里一台机器时选项就是组名」，并断言选中一项后下拉的值同时带上机器与组。三个引擎均通过。
