# v0.1.19

探针页面的设备地址接口改了形状：**一台设备一条记录**，记录里只留设备名与两个地址 —— `{node_name,ipv4?,ipv6?}`。两个地址各取该机器最近一次的观测值，只有一族就只出现那一个字段，两族都有就都给，客户脚本不必先判断机器是单栈还是双栈；原来「优先 IPv4」的取舍去掉了，接口把机器实际有的地址照实给出。机器离线、观测时间、归属地、节点 id 这些字段一并去掉，这条路径也不再向地区查询服务发请求。

历史趋势的上行与下行合并到一张图上共用一条纵轴：上行是品牌色实线，下行是绿色虚线，图下带图例，读数行与滑块提示都同时给出两个方向。速率单位固定为 MB/s，不再自适应成 KB/GB（两条曲线共用纵轴时单位不能随数值跳），进位与面板其余位置的字节显示一致。原来的「1 分钟负载」指标位去掉，指标只剩 CPU、内存、磁盘、上行/下行；负载仍由 Agent 上报，只是不再绘图，也不再把流量点因为它缺测而抹掉。合并之前发出去的链接（`?metric=upload_bps` 或 `download_bps`）会落到合并后的曲线上。

支付核对按「接口在、功能不在」的口径重新分级：该协议没有查单能力（原版 EPUSDT）时返回 `not_implemented` HTTP 500，不再是 422 —— 缺的是服务端实现，不该让调用方以为改改参数就能成功。适配器**配置**错误仍在加载配置时拒绝，语义不变。

WebSSH 默认打开 Agent 的配置目录 `/etc/tfp-agent`（目录不在时退回原来的位置），省掉每次手动 `cd`；`HOME` 仍指向真实家目录。**这一条在 Agent 二进制里，需要重跑接入命令更新 Agent 才生效**，面板升级不影响。

浏览器测试与真实 Go/SQLite 后端集成测试在 chromium/firefox/webkit 三个引擎通过；接口文档与 OpenAPI 描述同步更新。
