# v0.1.45

优化 TCP 单连接起速和持续吞吐，修复主租约尾部不足一个数据块时，已有备用租约仍无法使用而导致转发卡住的问题。

## 更新内容

- TCP 持久化额度窗口按实际需求从 256 KiB 扩大至最多 2 MiB，空闲后回收增长目标，小租约继续使用较小窗口。新额度仍须先落盘同步成功才可消费，账户每 Agent 的责任上限仍为 8 MiB，TCP 每规则上限由 1 MiB 调整为 4 MiB；UDP 继续使用原容量。
- 选择租约时检查是否足够覆盖当前数据块；使用备用租约或主租约只剩不足 32 KiB 时，主动结算主租约余量并推进切换，避免非整块尾部或空闲上传窗口长期阻止下载。
- 下一租约由独立工作协程预取，避免被慢用量上报、确认或退租阻塞。首次活跃窗口即可提供速率样本；预取仍有实际消费和有限预算约束，用量唤醒按至少 25 ms 合并。
- 配置 ACK 因预取或退租返回版本冲突时，快速重新拉取配置并保留短暂退避。
- Mux 单流接收窗口从 256 KiB 扩大至 32 MiB，提高高延迟线路可承载的在途数据量，与旧 Yamux 对端互通。慢读取流可能使用更多内存，现有连接和流数量限制继续生效。
- 随机填充和 TLS mimic 直接编码到可复用缓冲，减少载荷分配与复制；协议、认证和 TLS 校验保持兼容。TCP 继续使用机器已有的内核拥塞控制，包括 BBR。
- 所有 Agent 的公共 TCP 路径采用本轮优化，单连接以持续 2 Gbps、突发 3 Gbps 为性能目标，多连接不增加新的统一速率上限，已配置的套餐限制继续执行。

## 性能与验证

Windows amd64、i5-10400F、Go 1.26.9，真实回环 TCP、TLS/random-padding 与实际计量路径，128 MiB 单流三轮均值由约 316 MB/s 提升到 564 MB/s；每次 WAL 同步额外等待 3 ms 的对照由约 62 MB/s 提升到 464 MB/s。

超过 30 秒的单流测试运行实际 Agent 和 HTTP 用量确认，测试服务提供固定大额有限租约：用量响应延迟 100 ms 时达到约 4.42 Gbps；同时每次同步额外延迟 3 ms 时达到约 3.30 Gbps。两者均持续确认超过 4096 个窗口，最大单次读取间隔约 33 ms 和 24 ms。这是开发机数据路径证据，商用数据库满负载、Linux 公网和每台节点的 2/3 Gbps 仍需实测。

实际 Go/SQLite 商业账本回归覆盖直连、安全直连/random-padding 和 TLS Mux 的 48 MiB 持续下载、小初始租约、非整块上传及慢用量响应，核对精确计费和租约切换。回归还覆盖同步前拒绝发送、同步期间扣量、磁盘故障、恢复幂等、正常停止后的旧容量兼容、升级候选窗口保护、旧 Mux 对端及预取独立性。本地 Go 全量、vet 和相关包 race 已通过；Linux 全仓 race、三库、监督进程/systemd、HTTPS、前端和双架构 Docker 验证见本版本 GitHub Actions。方法、边界和复测要求见 [持续吞吐说明](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.45/docs/tcp-throughput-target.md)。

## 升级与恢复

升级面板及入口、相关中转和出口 Agent，才能获得整条路径的改进。已初始化可信升级能力的节点可自动跟随面板升级，也可在探针页点击「升级 Agent」；v0.1.36 等旧节点仍需先重跑完整接入命令初始化公钥，详见 [Agent 自动升级](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.45/docs/agent-auto-upgrade.md)。升级会重启进程，短暂中断已有连接。

本版不新增数据库迁移，保留数据库、证书、部署参数及 Agent 当前账本。WAL/checkpoint 格式编号仍为 2，但旧版本不支持扩大后的窗口。受管升级健康确认期间暂不扩大，监督进程提交成功后才启用增长，保留启动失败回滚能力。正常停止会结算并压缩账本，可退回 v0.1.44；若扩大窗口后异常退出，手动降级前须先用本版恢复并正常停止。不得删除账本或恢复已消费的旧状态。

异常恢复会按原租约保守计入无法证明未用的窗口余量，本轮每 TCP 规则最多 4 MiB、每账户每 Agent 最多 8 MiB 的责任上限同样适用，反复异常退出可能累积。

附件包含 Linux amd64/arm64 二进制包、两架构 Docker 安装包、安装管理器、Compose 与两份 SHA256 清单。面板包和镜像均携带双架构 Agent 与发布清单。发布不代表已部署到用户服务器。
