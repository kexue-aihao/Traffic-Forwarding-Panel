# v0.1.46

优化单连接和多连接在控制请求延迟较高时的 TCP 起速与额度续接，减少等待配置确认、备用额度失效及反复回到小额度造成的吞吐下降。

## 更新内容

- 预取速率估计按经过时间衰减，避免每 100 ms 检查时快速丢失近期需求；首次消费使用活跃窗口开始时间，避免空闲阶段压低估计。
- 使用缓存配置转发时，预取和用量结算在首次配置 GET/ACK 期间立即独立运行；探针发布及升级健康确认仍遵循首次配置尝试。
- 配置 GET/ACK 在配置锁外运行，慢 ACK 不再阻止备用额度应用；晚到的旧响应不会覆盖已应用的新配置。
- 新 Agent 可请求面板在预取/退租响应中直接附带完整授权配置，减少额度生效前的额外请求等待。配置仍执行普通接口的身份、策略、租约和持久化校验；旧 Agent/面板保持原响应兼容，配置生成失败时正常轮询重试。
- 写入退租账本前复核当前规则，避免正在预取的主额度提前退租；即将到期的授权继续按原逻辑停止消费。已确认退租且没有备用额度时，有限替代额度沿用此前学到的预算。
- PostgreSQL/MySQL 的租约刷新先按账户顺序加锁，再锁定节点；退租先锁定节点再退款，避免与预取、配置刷新形成死锁。MySQL 只读配置使用一致的可重复读快照，避免串行读的共享锁阻塞续接。锁定前后发现新增账户规则时重新获取配置，保留原授权校验。
- 保留有限分配、账户预留与 WAL 责任上限、准确计费和先落盘后转发约束。TCP 继续继承机器现有拥塞控制，包括 BBR；多连接不增加统一速率上限，已有套餐限制继续执行。

## 性能与验证

Windows amd64、i5-10400F、Go 1.26.9，实际 Go/SQLite 商用账本与 Agent，顺序对照 v0.1.45 与本版；数据面为回环 TCP，所有 Agent 控制 HTTP 请求额外延迟 240 ms。每条规则一个或八个连接，初始额度 16 MiB，2 GiB 下载单轮结果如下（单位 Gbps）：

| 路径 | 单连接 v0.1.45 → 本版 | 八连接 v0.1.45 → 本版 |
| --- | --- | --- |
| 直连 | 0.94 → 2.82 | 1.35 → 2.95 |
| TLS Mux + random-padding | 1.62 → 2.46 | 1.21 → 3.27 |

另有 512 MiB、60/240 ms、单连接/八连接及直连/TLS Mux 的三轮对照。各场景逐字节校验载荷，并核对用量、有限额度切换和退租。仍有个别额度切换等待，以上不代表 Linux 公网或所有机器已达到持续 2 Gbps、突发 3 Gbps；控制请求延迟模拟也不等于数据面 TCP RTT。完整方法和边界见 [控制延迟性能说明](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.46/docs/tcp-control-latency-performance.md)。

本地全仓 race、vet、计费倍率/预留回收、配置并发、身份校验、到期授权及 Linux 双架构构建通过。Linux 全仓 race、三库、升级监督进程/systemd、HTTPS、浏览器及双架构 Docker 验证见本版 GitHub Actions。

## 升级

需同时更新面板及相关入口、中转和出口 Agent，才能获得完整效果；仅更新 Agent 时，旧面板不会启用附带配置的响应。已初始化可信升级能力的节点可自动跟随面板升级，也可在探针页点击「升级 Agent」；旧节点首次初始化见 [Agent 自动升级](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.46/docs/agent-auto-upgrade.md)。Agent 升级会重启进程，短暂中断已有连接。

本版不新增数据库迁移或 WAL 格式变化，保留数据库、证书、部署参数和现有账本。自适应 TCP 窗口的降级与异常恢复边界沿用 v0.1.45，不得删除账本或恢复已消费的旧状态。

附件包含 Linux amd64/arm64 二进制包、双架构 Docker 安装包、安装管理器、Compose 与两份 SHA256 清单。面板包和镜像均携带双架构 Agent 及发布清单。发布不代表已部署到用户服务器。
