# v0.1.44

继续优化 TCP 单流转发，并在探针开机时长处增加启动时间和每三秒刷新的当前时间提示。

## 更新内容

- TCP 正常补充额度时，将旧窗口用量进度和新窗口预留合并为一次 WAL 同步，减少磁盘等待。新额度仍须持久化成功后才能使用，保留租约、限速、责任边界和故障恢复约束。
- TCP 只在实际等待限速或补充额度时创建超时上下文，减少逐块分配；继续检查当前规则、租约有效期和账户共享速率。
- 混淆帧头与内容合并成一次底层写入，并复用连接读写缓冲，减少 TLS 写入与内存分配，保持原协议格式和随机填充行为。TCP 继续继承机器已经设置的内核拥塞控制，包括 BBR。
- 悬停探针开机时长可查看机器启动时间、当前时间和采样状态；统一显示上海时间 UTC+8，当前时间按浏览器时钟每三秒刷新。支持键盘聚焦、手机点击、Esc 关闭和窄屏布局。
- 新 Agent 上报系统启动时间；旧 Agent 按采样时间和开机时长估算并标注。离线时保留最后上报的启动信息，当前时间继续更新；实时推送可更新已打开的提示。
- 新 Agent 遇到旧面板拒绝新增启动时间字段时，会以原格式重试；成功后缓存兼容模式，五分钟后重试新字段，避免升级顺序造成探针上报中断。

## 性能与验证

Windows amd64、i5-10400F、Go 1.26.9，真实 TCP 回环、TLS/random-padding、实际 Runtime/Store 计量，每轮持续单流下载 128 MiB，三轮均值从约 186 MB/s 提升到 327 MB/s（约 76%）。每次真实同步额外等待 3 ms 的对照从约 32 MB/s 提升到 63 MB/s。每 32 KiB 的正常计量同步次数从约 0.253 降至 0.126。完整方法和结果见 [TCP 优化说明](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.44/docs/tcp-refill-performance.md)；上述结果不是公网 VLESS 或目标 Linux 节点的速度保证。

本地回归覆盖未同步额度拒绝发送、同步期间持续扣量、磁盘故障、部分 WAL 写入与恢复幂等、并发双向额度、短写和帧兼容。Go 全量、vet、关键包 race、三浏览器契约、真实 Go/SQLite 面板及 TLS 配置界面测试通过。Linux 全仓 race、三库、systemd、HTTPS 与双架构 Docker 验证结果见本版本 GitHub Actions。

## 升级与附件

升级面板后，新时间提示即可使用；更新 Agent 可获得系统启动时间及本轮吞吐优化。入口计量优化需要更新入口 Agent，混淆封装优化需要更新实际隧道两端。已初始化升级能力和公钥的节点可以自动跟随面板升级，也可以在探针页点击「升级 Agent」。原有 v0.1.36 等旧节点仍需先重跑一次完整接入命令，详见 [Agent 自动升级](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.44/docs/agent-auto-upgrade.md)。

保留数据库、Agent 当前账本、证书和部署参数。本版不新增数据库迁移，Agent WAL/checkpoint 保持格式 2。升级 Agent 会重启进程并短暂中断现有连接；正常停止后替换程序，不恢复已被继续消费的旧账本。

附件包含 Linux amd64/arm64 二进制包（panel、agent、udpbench、双架构 Agent 与发布清单）、Docker amd64/arm64 安装包、安装管理器、Compose 和两份 SHA256 清单。发布不代表已部署到用户服务器。
