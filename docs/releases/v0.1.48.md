# v0.1.48

本版新增端口转发 JSON Lines 规则导入与导出，并修复 CI 中测试监听地址重复导致的偶发失败。

## 规则导入与导出

- 在「运营与任务 → 规则导入与导出」选择「端口转发 JSON Lines」，可粘贴每行一个 JSON 对象的配置；原有面板规则 JSON 格式继续提供。
- 导入前选择入口节点和设备组，再预览授权、端口冲突及配额，确认后创建导入任务。支持新增规则或按节点、协议、端口更新已有规则。
- `name` 作为规则名，`listen_port` 作为 TCP 监听端口，`dest` 作为目标地址列表；多个目标导入为等权后端。`proxy_protocol` 为 `0` 或省略时关闭发送，为 `3` 时按向目标发送 PROXY v2 转换。
- JSON Lines 导出支持此格式能表达的已启用 TCP 直连规则。无法表示的承载、共享入口、接收 PROXY Protocol 或后端权重等设置会提示错误；可改用面板规则 JSON 保留完整配置。

示例：

```jsonl
{"dest":["151.242.188.224:61547"],"listen_port":57005,"name":"YXTW1","proxy_protocol":3}
{"dest":["155.117.155.225:61547"],"listen_port":35267,"name":"YXJP5","proxy_protocol":3}
```

## CI 修复与验证

测试先同时占用一批临时 TCP 监听端口，再统一释放并应用配置，避免操作系统重复分配已释放端口，修复 `TestTCPSharedAccountResponsibilityAndIdleCreditReclaim` 的 `duplicate listener` 偶发错误。

本地全仓 `go test -race ./...`、该用例 race 重复 100 次、前端类型检查和构建、Chromium/Firefox/WebKit 浏览器回归均通过。浏览器回归覆盖单目标、多目标、导入预览、导入任务与 JSON Lines 下载。最终提交的 Linux、三数据库、HTTPS、systemd 及双架构 Docker 验证见本版 GitHub Actions。

## 升级

本版没有数据库迁移或 WAL 格式变化。使用完整发布包更新面板并保留原数据库、证书和部署参数；可信 Agent 自动升级继续提供。附件包含 Linux amd64/arm64 二进制包、双架构 Docker 安装包、安装管理器、Compose 和两份 SHA256 清单。
