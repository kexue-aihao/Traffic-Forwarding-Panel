# v0.1.42

TCP 转发改为在持久额度窗口内扣量并批量结算，减少安全直连等场景每个数据块等待磁盘同步造成的速度衰减。面板升级后默认分批升级 Linux Agent，并提供可信下载、健康确认和失败回滚。

## 更新内容

- 普通直连、安全直连、入口到出口、多级出口和共享 TLS 入口的 TCP 计量统一使用信用窗口。窗口内扣量与状态通知不等待磁盘锁；额度不足时暂停发送，支持取消和续租等待。
- 每个方向的窗口最多 256 KiB、每方向最多两个窗口；每规则未确认原始字节责任最多 1 MiB，每账户每 Agent 最多 8 MiB。后台每 100 ms 批量结算，空闲窗口回收，正常关闭与用量上报前刷新。
- 修复并发扣量等待内存锁期间使用过早时间戳的问题，避免新窗口用量早于创建时间而触发账本保护、导致 TLS 连接断开；双 CPU 下 64 路 TLS 并发竞态回归重复 100 次。
- Agent 自动跟随面板正式版本升级，默认开启，可在管理员站点设置关闭；每 5 秒检查在线节点，同时最多升级 2 台，离线节点恢复心跳后补升级。不会自动降级或跟随预发布版本。
- 自动升级复用持久运维队列和审计，采用面板数据库持久保存的 Ed25519 签名密钥。节点校验签名、HTTPS 下载和 SHA256，按 Linux amd64/arm64 选择产物；Docker 镜像与手动包均携带两种架构及发布清单。
- 下载失败等错误最多尝试 3 次，退避 30/120 秒；取消或回滚后的同一发布不反复重启。已领取的可信任务可在管理员停止新调度或面板再次更新时继续完成。
- 监督进程原子替换程序，等待新 Agent 在 60 秒内完成配置同步、ACK、用量与探针上报。启动失败或替换中断时恢复旧程序。官方安装的独立出口服务随升级及回滚重启，安装脚本支持替换运行中的二进制。

## 升级注意事项

升级完整面板包或镜像，保留原数据库与数据卷，并配置节点可访问的公开 HTTPS 地址。**已有节点首次需要重跑一次控制台接入命令以配置升级公钥与监督进程，此后才会自动跟随面板升级。** 保留节点原状态目录、证书和 profile；未初始化节点会在节点运维中提示。

公钥固定后，面板重启和镜像更新不会轮换密钥。数据库备份须包含 `cp_agent_update_settings`；重复接入发现公钥变化会停止，需先核实数据库恢复情况。仅替换面板程序、缺少发布清单或 HTTPS 地址时，自动升级显示不可用原因。

升级会短暂中断已有转发连接，两台并发上限不保证同一链路错峰。回滚仅恢复程序，不恢复旧账本。TCP 与 v0.1.41 继续使用 WAL/checkpoint 格式 2；更早版本仍须遵守既有迁移限制。异常退出时，无法证明未用的额度余量按恢复记录保守计费，反复异常退出可能累积多计。

详细流程见 [Agent 自动升级](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.42/docs/agent-auto-upgrade.md) 与 [TCP 计量和性能](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.42/docs/tcp-credit-performance.md)。

## 验证与附件

本地 Go 全量、相关竞态、vet、前端类型检查/构建、三浏览器契约及自动升级设置持久化检查、Linux 安装脚本模拟与 ShellCheck 通过；Linux amd64/arm64 产物已构建。Linux 监督进程测试、全仓竞态、三库、systemd、HTTPS 与双架构 Docker 安装验证见本版本 GitHub Actions。

Windows 本机安全直连回环诊断中，两轮平均吞吐约提升 3.96 倍；该结果不代表用户公网带宽、Linux 跨机吞吐/PPS/P99、5% 性能预算或 24 小时稳定性已验收。

附件包含 Linux amd64/arm64 二进制包（panel、agent、udpbench、双架构 Agent 与发布清单）、Docker amd64/arm64 安装包、安装管理器、Compose 和两份 SHA256 清单。
