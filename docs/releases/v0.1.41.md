# v0.1.41

设备组现在可以提供统一 TLS 共享入口。管理员在高级设置配置一个监听端口，获组授权的不同账户使用各自真实业务 SNI 创建规则，在同一入口节点复用该端口，覆盖入口直连和入口→出口。

## 更新内容

- 共享监听独立于用户父规则、规则租约和计费账户；每条 SNI 路由继续使用自己的目标、资源池、高级策略、协议检测、有限租约和计费。
- 增加路由及正常续租保留已有连接；删除、禁用、授权撤销或规则策略变更只撤销相关路由的连接。最后一条规则删除后，管理员入口仍继续监听。
- 更换端口先预留新端口，旧端口在节点成功 ACK 后释放，失败 ACK 保留预留。同端口 IP 重绑处理通配监听冲突，应用失败尝试恢复旧监听；配置过期关闭入口连接。
- 控制面统一校验入口归属、设备组授权、SNI 规范化与唯一性、节点端口冲突和导入。SQLite、PostgreSQL、MySQL 增量增加共享入口及端口预留表。
- 高级设置展示监听应用状态、Agent 升级需要及路由、连接、拒绝统计。启用共享入口的组中新 TCP 规则默认选择 SNI 共享，可取消使用独立端口；既有规则不自动迁移。
- 新增 `shared-tls-ingress-v1` 能力及独立配置清单，旧 Agent 不接收新入口及关联规则。保留原有同账户父子共享规则兼容路径。

## 升级与配置

升级面板及入口 Agent，在管理员入口组高级设置激活完整高级策略并启用「设备组共享 TLS 入口」，核对每个节点成功应用。默认关闭，默认监听 `0.0.0.0:443`；出口继续使用既有隧道与能力要求。规则填写客户端实际使用的业务域名，不自动分配域名。

共享入口默认 TLS 透传，不提供入口证书；目标服务证书必须覆盖业务 SNI。SNI 仅用于路由，业务身份认证仍由业务服务负责。仅支持可见 SNI 精确 DNS 名称，不支持通配或默认路由；普通 TCP、原生 UDP、空/未知 SNI 和 ECH 内层名称不加入共享入口。每个入口最多预留 64 个 SNI（包括禁用草稿），运行时最多 256 个并发连接。接收入站 PROXY protocol 仍需独立监听。

共享规则导入使用 `create` 模式；`update_by_port` 无法唯一标识规则而被拒绝。回退功能先关闭共享入口并等待节点 ACK，规则不会自动变为独立监听，使用新入口的节点应先移除入口配置再降级 Agent。升级前备份数据库与 Agent 状态；更早版本仍须遵守 v0.1.38 WAL 2 的迁移与回滚限制。

详细配置、API、生命周期、测试及基准见 [共享入口说明](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.41/docs/shared-tls-ingress.md)。

## 验证

本地 Go 全仓竞态检查及最终 Agent/平台/集成竞态回归通过；新功能分别在 SQLite、PostgreSQL、MySQL 验证。真实 TLS socket 与控制面→Agent→目标集成覆盖直连/出口、独立计费、路由更新与撤销、租约续期与停止、64 路由、分片 ClientHello、配置过期、IP 重绑/回滚及成功/失败 ACK 端口释放。

Go vet、前端类型检查/构建、Chromium/Firefox/WebKit 模拟与真实面板回归、共享入口专用浏览器测试以及 Linux amd64/arm64 编译通过。发布检查继续在 Linux 执行全仓竞态、独立协议客户端、三库、systemd、HTTPS 和双架构 Docker 安装验证，实际结果见本版本 GitHub Actions。

本机 TLS 回环基准不代表 Linux 跨机吞吐/PPS/P99、5% 性能预算或 24 小时稳定性已验收；完整性能指标仍需按既有验收手册实测。

附件包含 Linux amd64/arm64 二进制包（panel、agent、udpbench）、Docker amd64/arm64 安装包、安装管理器、Compose 和两份 SHA256 清单。
