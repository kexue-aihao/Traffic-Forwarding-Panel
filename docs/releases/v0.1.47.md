# v0.1.47

本版减少控制请求延迟波动时 TCP 持续传输的额度续接等待，针对起峰后速率反复回落的一个已复现软件瓶颈进行优化。国内公网线路的实际改善仍需升级后复测。

## 变更

- 活跃 TCP 规则结算退租时，可携带已有速率估计产生的有限预算。面板在原有授权配置刷新事务内提升备用额度、补下一份备用额度，并返回完整配置，减少一次独立预取 HTTP 往返。
- 预算提示绑定实际退租的主额度和当时的备用额度，兼容并发配置刷新；旧退租重放不能为后续空闲规则续配。空闲、小流量、UDP、无效提示和已撤销授权不启用该优化。
- 可选请求头兼容旧面板，原有请求 JSON 不变。每份计费预算最多 256 MiB、账户在途预留最多 512 MiB、两份租约、WAL 先落盘后消费和 TCP 每规则/账户每 Agent 4/8 MiB 责任限制继续生效。
- Linux socket 继续继承机器设置的拥塞控制，包括 BBR。多连接不增加统一速率上限，套餐资源限制继续生效。

## 验证与性能边界

同机 Windows amd64、SQLite 商业账本对照，每场景持续下载 8 GiB，初始额度 16 MiB。控制 HTTP 请求在启动一秒后按请求序号循环增加 360/480/600 ms 延迟，源端名义总速率为 2.4 Gbps。以下为单轮平均下载速率：

| 路径 | 连接数 | v0.1.46 → 本版，Gbps |
| --- | --- | --- |
| 直连 | 1 | 1.426 → 1.891 |
| 直连 | 8 | 1.501 → 2.156 |
| TLS Mux + random-padding | 1 | 1.473 → 2.159 |
| TLS Mux + random-padding | 8 | 1.784 → 2.152 |

独立预取由每场景 18–19 次降至一次，修改版四种场景均未出现整秒无数据，仍有短时读取等待。测试逐块校验载荷及精确计费。数据面为回环网络，仅模拟控制 HTTP 抖动，不代表公网 TCP RTT 或丢包，也不能确认国内线路截图的根因。直连单连接平均仍低于 2 Gbps，所有机器持续 2 Gbps、突发 3 Gbps 的目标尚未全面验收。完整方法、逐秒统计及本地 SQL 验证限制见 [TCP 抖动与续接说明](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.47/docs/tcp-jitter-performance.md)。

本地全仓 race、vet、SQLite/PostgreSQL 相关回归和 Linux 双架构构建通过。MySQL 本地完成租约相关商业/平台及针对性集成回归，使用临时测试实例的非默认同步参数，不作为断电持久性证据。最终发布提交的 Linux 全仓 race、标准配置三库、浏览器、HTTPS、systemd 和双架构 Docker 检查见本版 GitHub Actions。

## 升级

需同时更新面板及入口 Agent，并建议同步更新相关中转、出口节点以保持版本一致。仅升级其中一侧时继续兼容原流程，完整续接优化需要双方支持。已初始化可信升级能力的节点可自动跟随面板升级，也可在探针页点击「升级 Agent」；旧节点首次初始化见 [Agent 自动升级](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.47/docs/agent-auto-upgrade.md)。Agent 升级会重启进程，短暂中断已有连接。

本版没有数据库迁移或 WAL 格式变化，升级时保留原有数据库、证书、部署参数和账本。附件包含 Linux amd64/arm64 二进制包、双架构 Docker 安装包、安装管理器、Compose 和两份 SHA256 清单；面板包及镜像均携带双架构 Agent 和发布清单。
