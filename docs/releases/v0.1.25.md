# v0.1.25

修复新增套餐的类型与有效期单位不一致的问题，套餐支持日、周、月、年，购买、兑换和自动续费使用相同的期限计算规则。

## 更新内容

- 套餐类型与有效期输入联动：日套餐显示有效天数，周期套餐显示有效周数，月期套餐显示有效月数，年期套餐显示有效年数。最大单位为年，季度和半年可分别配置为 3 个月、6 个月。
- 套餐卡片、购买确认和编辑回填同步显示期限单位与数量；再次新增套餐时重置表单，避免带入上一次编辑内容。
- 周按 7 天计算；月、年按上海时区自然月、自然年计算，目标月份不存在对应日期时夹紧至月末，正确处理闰日。
- 购买、套餐兑换、自动续费共用到期计算；套餐编辑递增版本，只影响后续交易，历史购买快照和已购买权益保持原期限。流量叠加包仍只增加当前配额，不设置独立有效期。
- API 新增 duration_unit 与 duration_value，保留旧 months 输入兼容，并拒绝互相冲突的期限或非法数量。范围为天 1..3650、周 1..520、月 1..120、年 1..10，保留原 120 个月的期限范围。
- 补充数据库升级、旧备份恢复、期限校验、月末及闰日、购买/兑换/自动续费、快照不变性和真实浏览器编辑回显回归；支付配置浏览器测试等待实际保存响应，避免旧提示导致的竞态。

## 升级说明

本版将 commerce 数据库结构升级至版本 8，增加期限单位和数量。已有月套餐自动保留原月数，旧备份恢复后也会补充月单位，不修改现有权益到期时间。

升级前应保留数据库备份；Docker 安装脚本支持升级前备份。旧程序不能直接读取升级后的数据库，回退需使用对应的升级前备份。

本版不改变已保存的注册策略、支付配置或用户资料。本地预览数据库、账号和测试数据不会进入发布包。

## 验证与产物

修复已通过 Go 全量测试、go vet、前端类型检查与构建，以及 Chromium、Firefox、WebKit 的前端和真实 Go / SQLite 后端回归。本地 8080 预览已验证表单标签、前端构建一致性和原注册配置保留。

发布门禁包括完整 GitHub CI、三数据库回归、race、双架构编译及 Docker 安装检查，全部通过后发布。

提供 Linux amd64 / arm64、Docker amd64 / arm64 安装包，以及安装脚本和 SHA256 校验文件。
