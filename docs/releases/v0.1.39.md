# v0.1.39

本版本实现设备组全部高级参数的执行链路，覆盖直连入口、入口到出口、链式与反向服务。管理员在设备组高级设置显式启用完整策略后，控制面编译参数并下发给具备能力的 Agent；界面提供影响预览、阻断原因及运行诊断。

## 更新内容

- Host/SNI 规范化与允许/拒绝列表，跨组策略合并；明文 HTTP/1 逐请求及 h2c HPACK HEADERS 路径过滤，校验编码、请求边界、分块与 trailer。
- TCP/UDP 业务协议识别、TLS-only 与空 SNI 限制；UDP 禁用、恢复和 QUIC 到 UDP-over-TCP 切换均接入实际转发链路。
- 对已授权设备组对端优先 IPv6，TCP 地址竞速与回退；候选出口按权重选择，支持失败阈值、冷却和单次半开，业务发送后不重播。
- 普通 Agent 托管正向出口及反向 hub/connector，支持 TLS、tls_simple、WS、HTTP 四种反向载波。载波和逐规则业务凭据分离，精确校验规则、网络和目标。
- 节点本地 TLS profile 支持 CA、SNI、ALPN、TLS 1.3、服务器/客户端证书和 mTLS；TCP/QUIC 原端口证书轮换，授权变化撤销旧会话，服务续期避免旧定时器误关闭。
- 授权、组、规则、资源及节点能力变化发布相关配置。候选新增和权重调整保留健康连接，规则诊断报告实际载波、地址族、候选和策略拒绝数。
- Debian/Ubuntu、Red Hat 和 Arch 系接入脚本支持 `-F` 安装本地 profile，`-M -F` 显式迁移旧出口服务。

## 升级和激活

升级面板及入口、出口 Agent；在设备组高级设置勾选“启用完整高级策略”，提交 `advanced.policy_version=2`。存量配置保持旧策略行为，不自动激活。出口组使用完整策略时必须迁移到普通 Agent 托管出口，并在节点配置具备精确监听许可的本地 profile；旧独立出口不能提供完整策略执行能力。反向服务需配置 hub、出口身份、匹配的载波和 TLS profile，等待两端服务就绪。

profile 标签/路径/监听许可在启动时加载，修改后重启 Agent；证书、私钥和 CA 文件轮询更新。升级前备份面板数据库、Agent 状态与证书配置；从 v0.1.37 或更早版本升级仍需遵守 v0.1.38 的 WAL 2 迁移限制。回滚不能仅用旧 Agent 读取新状态；已消费额度不能通过恢复旧状态再次使用。

完整部署步骤、profile 示例、参数语义与回滚限制见 [高级设置交付说明](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.39/docs/advanced-settings-implementation.md)。

## 验证与边界

本地 Go 全量测试、相关 race、vet、前端类型检查/构建、Chromium/Firefox/WebKit 两套回归和 17 项安装器模拟检查通过。真实 socket 集成覆盖策略允许/拒绝/恢复、两个 Agent 的反向服务、TLS/mTLS、证书轮换、授权撤销、UDP 载波切换和 IPv6。发布流程补充 Linux 全量 race、SQLite/PostgreSQL/MySQL、真实 systemd、HTTPS 与双架构 Docker 安装验证；最终结果见本版本 GitHub Actions 记录。

HTTPS Path、HTTP3、DTLS 和 ECH 内层不解密；直连 UDP 没有远端解封装端点，继续使用原生 UDP。原生 QUIC DATAGRAM 覆盖普通单出口，链式与反向 UDP 使用 TCP 载波。候选限定同出口组、倍率和有效策略，最多 16 项。

Linux 跨机吞吐/PPS/P99、无策略 5% 性能预算、24 小时稳定性以及各发行版实机安装仍待隔离验收；功能回归不代表原生 UDP 性能指标达标。性能方法见 [UDP 验收手册](https://github.com/kexue-aihao/Traffic-Forwarding-Panel/blob/v0.1.39/docs/udp-performance-lab.md)。

附件包含 Linux amd64/arm64 二进制包（panel、agent、udpbench）、Docker amd64/arm64 安装包、安装管理器、Compose 和两份 SHA256 清单。版本发布不执行用户服务器部署。
