# TCP 控制请求抖动下的持续传输

2026-10-11，v0.1.47 基于正式版 v0.1.46 优化控制请求抖动时的额度续接。目标仍为单连接持续 2 Gbps、突发 3 Gbps，多连接不增加统一速率上限；套餐本身的资源限制继续生效。

## 本轮解决的等待

v0.1.46 的备用额度可以维持当前 TCP 连接，但主额度结算退租后，Agent 还需要再请求下一份备用额度。控制请求变慢时，这一轮往返可能让正在消费的备用额度耗尽。原有控制延迟测试已观察到接近一秒的读取等待；新增抖动测试进一步复现了每秒速率反复下降。

活跃 TCP 规则退租时，Agent 将已有速率估计产生的有限预算放入可选 `X-TFP-Lease-Prefetch-Budget` 请求头。面板确认最终用量并退租后，在原有授权配置刷新事务内提升备用额度、补下一份备用额度，再返回完整配置。Agent 仍按正常身份、策略、租约和持久化校验应用快照，减少一次单独的预取往返。

预算提示绑定到实际退租的主额度及当时的备用额度。并发 GET 已提升同一备用额度时仍可补齐；过期请求和退租重放不能给后续空闲额度续配。Agent 仅在最近五秒观察到实际流量、且消费达到原有预取门槛时携带提示。空闲、小流量、UDP、未请求附带配置、无效提示和已撤销授权不启用这条优化。旧面板忽略可选请求头，请求 JSON 仍只有原有两个字段，继续使用独立预取；旧 Agent 的退租响应保持原状。

商业分配器仍在事务内执行倍率换算、配额与预留检查。每份计费预算最多 256 MiB，账户总在途计费预留最多 512 MiB；不增加同时发布的两份租约或每规则在途分配数量限制。WAL 先同步后转发、TCP 每规则/账户每 Agent 4/8 MiB 责任边界保持生效。没有数据库迁移或 WAL 格式变更，Linux socket 继续继承机器现有拥塞控制，包括 BBR。

## 持续对照方式

使用同一 Windows amd64、Intel i5-10400F、Go 1.26.9 环境，顺序运行 v0.1.46（`b9ee17457e19d94fe95fe18f0477a523d4cc550e`）和 v0.1.47。每场景下载 8 GiB，初始额度 16 MiB，后续额度经过实际 Go 面板、SQLite 商业账本和 Agent；隔离测试账户配额设为 16 GiB。

开始一秒的控制 HTTP 请求额外延迟为 120 ms，之后按请求序号在 360/480/600 ms 间变化。数据源按约 4 MiB 分批提供总计名义 2.4 Gbps 的业务数据，写阻塞时间计入批次间隔，不积累无限追赶突发。操作系统计时和 TCP 缓冲会影响实际每秒速率。覆盖直连和真实 TLS + Yamux + random-padding，每条规则一个或八个连接；记录每秒速率、最大读取间隔、独立预取/退租次数，并逐块核对载荷以及下载量加每连接一个上传标记的精确计费。

最终单轮 8 GiB 对照结果，下载计时旧版为 38.53–48.21 秒、修改版为 31.83–36.34 秒：

| 路径 | 连接数 | 平均 Gbps，旧 → 新 | 后半段完整秒平均 Gbps，旧 → 新 | 最大读取间隔 ms，旧 → 新 | 整秒无数据次数，旧 → 新 |
| --- | --- | --- | --- | --- | --- |
| direct | 1 | 1.426 → 1.891 | 1.349 → 1.857 | 1612 → 628 | 2 → 0 |
| direct | 8 | 1.501 → 2.156 | 1.424 → 2.147 | 1727 → 672 | 9 → 0 |
| TLS Mux + random-padding | 1 | 1.473 → 2.159 | 1.422 → 2.147 | 1415 → 331 | 3 → 0 |
| TLS Mux + random-padding | 8 | 1.784 → 2.152 | 1.808 → 2.147 | 1975 → 1095 | 8 → 0 |

多连接的最大间隔取任一连接，整秒无数据按全部连接汇总统计。每场景经过约 32 次退租，独立预取由 18–19 次降到一次；其他备用额度随退租响应补齐。后半段完整秒指逐秒样本的后半段，不含结束时不足一秒的尾部。这是单轮对照，不是多轮置信区间。修改版没有出现整秒无数据，仍有短时读取等待；直连单连接平均仍低于 2 Gbps，不能据此认定目标已全面达成。

原始逐秒日志为 `.local/tcp-stability-20261011/baseline-final.txt`、`optimized-final.txt`，汇总为同目录 `comparison.json`。早期 1 MiB 左右分批和未加入空闲保护的测量保留在其他日志中，未混入上表。

此测试模拟控制 HTTP 延迟与抖动，数据面使用回环网络。源端分批提供数据用于观察持续消费，不代表公网 TCP RTT 或丢包模拟。读取间隔包括等待数据和额度的时间，不等于连接断开；本地改善不能确认用户截图中的国内线路根因，也不能据此宣布全部机器达到目标。

复现持续测试（不设置变量时每场景为 1 GiB）：

```sh
TFP_TEST_TCP_DOWNLOAD_MIB=8192 go test ./internal/integration \
  -run '^TestTCPDownloadAcrossControlPlaneJitter$' -count=1 -v -timeout=8m
```

原有固定 60/240 ms 控制延迟测试继续保留：

```sh
go test ./internal/integration -run '^TestTCPDownloadAcrossControlPlaneLatency$' -count=1 -v -timeout=5m
```

## 回归验证

- `go test -race ./... -count=1 -timeout=10m` 全仓通过，包括固定控制延迟、新增抖动、WAL 崩溃恢复、精确结算、额度到期/撤销和并发传输；`go vet ./...`、Go 格式和 `git diff --check` 通过。
- SQLite 与 PostgreSQL 18.6 的新增退租回归覆盖 1、1/2、3/2、3 倍计费、账户 512 MiB 上限、剩余配额、无效提示、旧响应、空闲、UDP、撤销和旧请求重放。PostgreSQL 同时通过租约相关商业/平台回归及单连接、八连接真实下载。
- MySQL 8.4.6 顺序通过商业/平台租约回归；新增集成验证通过活跃补充、账户上限、剩余配额和单连接实际下载的精确计费。首次并行测试包在本地创建临时库阶段超时，随后顺序运行，并在本任务启动的测试实例上临时使用 `innodb_flush_log_at_trx_commit=2`、`sync_binlog=0` 降低同步开销。此组验证事务及并发行为，不验证 MySQL 断电持久性；产品配置没有修改。
- 面板与 Agent 的 `CGO_ENABLED=0` Linux amd64/arm64 四个构建通过。OpenAPI 重新生成包含可选预算请求头，共 146 个操作。

本地验证记录在 `.local/tcp-stability-20261011/full-race.txt`、`postgres-checks.txt`、`mysql-checks-serial.txt`（商业/平台包）、`mysql-targeted.txt`（新增集成场景）。

## 使用与公网复测

优化需要同时更新面板和入口 Agent，不需要新增面板设置。国内线路还需要用同一客户端、同一测速后端对比绕过转发与经过转发的单连接结果，并记录每秒速率、入口/中转/出口实际版本、承载及 Mux/混淆、Agent 到面板的请求耗时、数据面 RTT/重传、CPU 与磁盘同步延迟。建议每次持续至少 30 秒，重复三轮；国内 2000M 目标的容量也需要与 3 Gbps 突发目标分开验收。
