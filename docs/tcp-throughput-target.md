# TCP 持续吞吐、起速和租约切换

2026-10-11，v0.1.45 在正式版 v0.1.44 基础上继续优化。目标为所有 Agent 共用数据路径在有足够线路、CPU 和磁盘能力时，单连接持续至少 2 Gbps（250 MB/s）、突发至少 3 Gbps（375 MB/s）；多连接不添加新的总速率上限，已配置的套餐资源限制继续执行。公网各节点仍需逐机复测。

## 修改和原因

- TCP 按实际需求将窗口从 256 KiB 逐步扩大至最多 2 MiB。快速消耗第一个窗口后就请求扩大；窗口切换时保留目标大小，空闲一秒后清理。小租约按其预算缩小窗口，不在加载空闲规则时预占额度。每方向仍最多两个窗口，每条 TCP 规则责任上限改为 4 MiB，每账户每 Agent 仍最多 8 MiB；UDP 的窗口和规则上限保持 256 KiB/1 MiB。
- 用量进度和新预留仍先按顺序写入 WAL 并同步成功后才发布。计算同批新预留时计入已结算或关闭窗口释放的规则/账户责任；租约总预算仍包含旧责任，避免未持久化时恢复可消费预算。同步期间允许扣减原先已落盘的窗口。
- 租约选择检查是否足够覆盖当前数据块。此前主租约有一字节剩余时也会被选中，随后无法提供 32 KiB 的读取块，导致已有备用租约不能使用；持续下载回归复现了该卡死。开始消费备用租约后主动结算主租约的余量，并请求面板提升备用租约，避免空闲上传窗口或非整块尾部长期阻止后续预取。
- 租约预取有独立工作协程，每 100 ms 检查，并合并最短 10 ms 的唤醒。它不再排在用量 POST、确认和退租之后。首次活跃窗口可提供速率样本；有实际消费才申请备用额度，仍沿用 16–256 MiB 的有限预取预算。
- 用量上报的连续唤醒按至少 25 ms 合并，减少高速流每完成一个窗口就触发一轮面板数据库事务。没有面板确认时仍受 4096 条待确认记录上限约束。
- 预取和退租可在配置 GET 与 ACK 之间更新期望版本。ACK 返回 409 后主动拉取当前配置，连续冲突保留 10 ms 退避，避免等待完整五秒轮询或错误退避的一秒。
- Mux 单流接收窗口从 256 KiB 改为 32 MiB，继续通过 Yamux 原有窗口更新与旧端互通。高延迟线路需要较大的在途字节数，例如 2 Gbps、56 ms 对应约 14 MB。接收缓冲按收到的数据分配，慢读取流可占用比旧版更多的内存；连接/流数量限制仍生效。改善下载需更新接收该方向数据的一端。
- 随机填充及 TLS mimic 直接编码进连接写缓冲，减少每帧的一次完整载荷分配和复制。保持随机填充、协议字节格式、认证和 TLS 校验，不修改拥塞控制；Linux socket 继续继承机器的 BBR 设置。

没有增加统一的 2/3 Gbps 限速器，也没有在租约或账本失败时放行未授权数据。单连接本身没有新的固定速率上限。

## 本地性能证据

Windows amd64、Intel i5-10400F、Go 1.26.9，真实回环 TCP、TLS、random-padding、Runtime 和 Store。v0.1.44 与优化版均发送 4096 个 32 KiB 块（128 MiB），预热 16 块，三轮；WAL 真正同步，慢磁盘模式在每次同步前额外等待 3 ms。

| 模式 | v0.1.44 三轮 MB/s | 优化后三轮 MB/s |
| --- | --- | --- |
| 安全直连、实际计量 | 299.22 / 318.62 / 330.47 | 533.34 / 576.99 / 582.22 |
| 实际计量、额外 3 ms/同步 | 62.00 / 62.23 / 61.88 | 449.38 / 466.62 / 474.66 |

普通计量三轮均值约 316 → 564 MB/s，慢磁盘对照约 62 → 464 MB/s。正常同步频率从每 32 KiB 的约 0.126 降至 0.0164；载荷分配从约 44 KiB/15 次降至约 400 B/6–7 次。原始本地输出在 `.local/tcp-throughput-20261011/`。这些相邻测试存在调度波动；未计量与计量路径的排序也受读写调度影响，不据一次排名判断 TLS 性能上限。

新增控制循环基准运行实际 Agent 和 HTTP 用量确认，隔离的测试服务返回固定的大额有限租约，避免控制面新额度不足干扰数据路径测量；它不是商用面板数据库满负载测试。两种持续场景均传输超过 4096 个窗口，计时区间内持续确认账本：

| 单连接持续场景 | 载荷/持续时间 | 吞吐 | 最大一次读取间隔 |
| --- | --- | --- | --- |
| 用量响应额外等待 100 ms | 536643 × 32 KiB / 约 31.8 s | 552.76 MB/s，约 4.42 Gbps | 32.91 ms |
| 每次同步额外等待 3 ms、用量响应额外等待 100 ms | 450543 × 32 KiB / 约 35.8 s | 412.20 MB/s，约 3.30 Gbps | 23.98 ms |

可复现短时对照和持续场景：

```sh
go test ./internal/agent -run '^$' -bench '^BenchmarkSecureDirectDownload$' -benchtime=4096x -count=3 -timeout=3m
go test ./internal/agent -run '^$' -bench '^BenchmarkSecureDirectDownload/secure_direct_controlled_100ms$' -benchtime=30s -count=1 -timeout=3m
go test ./internal/agent -run '^$' -bench '^BenchmarkSecureDirectDownload/secure_direct_controlled_3ms_100ms$' -benchtime=30s -count=1 -timeout=3m
```

实际 Go HTTP 应用和 SQLite 商用账本的持续下载回归覆盖 direct、secure-direct/random-padding、TLS Mux，单连接下载 48 MiB，初始租约 16 MiB，上传一个非整块标记，同时延迟用量上报 100 ms。核对总计费字节、主租约结算和备用预取，三轮均通过；本轮最大读取间隔 3–18 ms。测试未设置可波动的吞吐断言，不将开发机计时当成 CI 带宽验收。

## 升级、恢复和边界

优化代码在入口、普通出口、多级出口、反向载体及共享 TLS 入口的公共 TCP 计量/中继路径生效。入口要更新才能获得额度与续租优化，相关隧道两端要更新才能获得封装和各接收方向的 Mux 窗口优化。面板无需数据库迁移。

WAL/checkpoint 格式编号仍为 2，但窗口新增可选的 TCP 标记，旧版本不支持扩大窗口的容量。升级测试期暂不扩大窗口，直到监督进程提交健康成功并删除升级日志；这使启动失败的候选版本仍可由上一版回滚。正常停止后会结算窗口并压缩账本，支持退回 v0.1.44。若扩大窗口后的进程异常退出，须先用本版恢复并正常停止，再退回旧版；不得删除账本或恢复已消费的旧状态。Linux 自动回滚、systemd 和发布包验证以本版本 GitHub Actions 结果为准。

异常恢复按原租约保守计入无法证明未用的窗口余量；本轮每 TCP 规则最多 4 MiB、账户每 Agent 最多 8 MiB 的责任上限也适用于崩溃多计，反复异常退出可累积。磁盘故障、额度/租约到期、规则撤销、账户限速和离线账本压力仍可能暂停或关闭连接。

回归覆盖扩大窗口的同步前拒绝发送、同步期间持续扣量、追加和同步故障、恢复幂等、正常停止后的旧容量账本兼容、小预算双向计量、账户责任上限、旧 Mux 对端以及阻塞用量 POST 时的预取/配置更新。Go 全量、vet 和 Agent/tunnel/integration 竞态检查通过；后续变更的相关用例另行重复验证。Linux amd64/arm64 交叉构建和版本/架构校验在测试包阶段完成，Linux 实机能力尚未验收。

公网验收需在入口、每级中转及出口核对实际运行版本，记录相同客户端/目标的直连单线程速度、CPU、磁盘同步时延、RTT、丢包、承载、Mux 和混淆策略；测速至少 30 秒、三轮，同时保留每秒速率与错误日志。`timing-perturb` 会主动插入等待，不适合作为高速目标的默认配置。所有机器按相同目标测量，但有限线路和硬件不能靠软件保证统一 2/3 Gbps。
